# 비공개 방문 기록

성과 대시보드의 왼쪽 상단 방패 로고 **위 빈 공간**을 세 번 연속 누르면 방문 통계 로그인이 열립니다. 관리자 비밀번호는 방문자의 체류 시간, 브라우저·기기 등 방문 기록을 열람할 때만 사용합니다. 지정된 비밀번호는 서버에서 검증하며 소스·정적 번들·브라우저 저장소에 넣지 않습니다. 관리자 로그인만으로는 일정 메모나 상담 기록을 볼 수 없습니다.

클릭 영역은 사이드바의 맨 위32px 전체 너비입니다. 상단 브랜드와 이 영역에서만 글자 선택·이미지 끌기를 막으며 일반 본문 선택과 로고 링크는 유지합니다. 이전 화면을 열어두었다면 새로고침해 최신 버전을 불러옵니다. [운영 배포 확인](DEPLOYMENT.md).

## 기록과 표시

- 익명 방문자 번호, 접속 시각, 브라우저·기기 종류, 열어본 메뉴와 메뉴별 활성 화면 체류 시간을 표시합니다. 시간은 한국 시간입니다.
- 같은 브라우저의 재방문은 서명된 익명 쿠키로 구분합니다. 이름·연락처·원본 IP·전체 User-Agent·외부 방문 경로·입력 내용은 수집하지 않습니다. 쿠키 삭제나 다른 브라우저 사용 시 다른 방문자로 표시됩니다.
- 다른 탭이나 최소화된 화면에서 보낸 시간은 제외합니다. 30초 간격 활동 신호와 메뉴 이동·화면 숨김·종료 신호를 저장합니다. 종료 신호를 받지 못하면 정확한 퇴장을 추정하지 않고 마지막 활동을 표시합니다.
- 관리자 페이지는 수집 대상에서 제외하며 로그인한 관리자의 익명 방문자는 통계에서도 제외합니다. 유효한 운영 기기 세션이 있는 동안에도 방문을 기록하지 않습니다. 브라우저의 DNT·GPC 설정을 존중합니다.
- 오늘·최근 7일·최근 30일 조회와 페이지 이동을 제공합니다. 기록은 배포 후부터 쌓이며 과거 방문은 복원하지 않습니다. 30일이 지난 기록은 일일 cron과 방문/관리자 조회 시 제한된 배치로 정리합니다.

## 서버 설정

기존 Worker와 D1을 재사용합니다. `0004_admin_analytics.sql`은 관리자 세션·익명 방문자·방문·메뉴 활동·요청 제한 테이블만 추가합니다. 광고 자료와 Instagram 인증 테이블은 변경하지 않습니다.

Cloudflare Secret 바인딩:

| 이름 | 형식 |
| --- | --- |
| `ADMIN_PASSWORD_VERIFIER` | `v1$<무작위 16바이트 salt의 hex>$<SHA-256(salt + ':' + password)의 hex>` |
| `ADMIN_ANALYTICS_KEY` | 최소 32자의 무작위 키. 익명 쿠키 서명·요청 제한용 HMAC에 사용 |

실제 비밀번호·검증 해시·키는 문서나 저장소에 기록하지 않습니다. 기존 `TOKEN_ENCRYPTION_KEY`는 보존합니다. 새 바인딩이 없으면 수집을 시작하지 않으며 관리자 화면은 설정 대기를 표시합니다.

관리자 세션은 무작위 토큰의 해시만 D1에 보관하며 8시간 후 만료됩니다. 관리자 쿠키는 `HttpOnly; Secure; SameSite=Strict`, 익명 방문자 쿠키는 `HttpOnly; Secure; SameSite=Lax`로 30일 유지됩니다. 로그아웃에는 CSRF 검증, 로그인에는 IP 기반 키 해시별·전체 요청 제한을 적용합니다. 모든 관리자 응답은 `no-store, private`이며 비밀번호 없는 통계 요청은 401입니다.

수집 API는 동일 출처, JSON 크기·메뉴·이벤트 ID·순서·소유권·누적 시간 상한을 검증합니다. 쿠키 첫 발급 요청을 직렬화해 빠른 메뉴 전환에서도 한 익명 방문자로 유지합니다. 전송 실패는 공개 사이트 이용을 막지 않습니다.

## 비밀번호 없는 운영 기기

운영 권한으로 Wrangler에 로그인한 PC에서 저장소 루트의 `node scripts/issue-staff-device.mjs --remote`를 실행합니다. Windows에서는 출력된 사용자 전용 HTML 파일을 업무용 브라우저로 열고 **이 브라우저를 운영 기기로 연결**을 누릅니다. 링크는 24시간 동안 한 번 유효합니다. 만료되거나 다른 기기가 필요할 때 같은 명령으로 새 파일을 발급합니다.

대시보드와 콘텐츠 캘린더의 일정 제목·날짜 및 게시물, 아래 일곱 항목으로 구성한 문의 목록은 누구나 볼 수 있습니다. 일정 메모·편집, Instagram 계정 연결, 고객 상세 정보 열람과 문의 수정에는 운영자가 등록한 브라우저를 사용합니다. 새 담당 기기는 소유자가 발급한 일회용 등록 링크를 한 번 열면 됩니다. 링크를 다른 사람에게 공유하거나 문서·채팅·저장소에 남기지 않습니다.

마이그레이션 `0013_staff_access.sql`은 방문 통계와 독립된 등록 링크·기기 세션 테이블을 추가합니다. 등록 링크는 짧은 유효기간 안에 동일 출처에서 한 번만 사용할 수 있습니다. 세션 쿠키는 `HttpOnly; Secure; SameSite=Lax`이며 90일 후 만료됩니다. 만료까지 30일 미만일 때 운영 세션을 다시 확인하면 그 시점부터 90일로 갱신합니다. 쿠키나 비밀번호를 JavaScript 저장소에 복사하지 않습니다. 운영 세션을 삭제하면 일정 변경·문의 조회·진행 중인 Instagram 연결 승인에 더 이상 사용할 수 없습니다. 운영 기기를 등록해도 방문 기록은 열리지 않습니다.

## 문의·상담

휴대폰이나 PC에서 `#inquiries`를 열면 등록 순서가 최신인 문의부터 한 건씩 표시됩니다. 접수일, 관심 상품, 지점, 문의 채널, 유입 경로, 담당자, 진행 상태를 공개합니다. 같은 날 같은 유형의 문의를 여러 건 받으면 각각 표시합니다. 좁은 화면에서는 표 안에서 옆으로 밀어 나머지 열을 볼 수 있습니다. 고객 이름, 연락처, 상담 메모, 고객 유형, 연결된 광고와 개별 기록 식별자는 담당자용 API에서만 취급합니다.

목록은 화면을 보고 있는 동안 60초마다, 다른 앱이나 탭에서 돌아올 때 다시 조회합니다. 담당자가 수정 중인 입력값은 작성하던 대로 유지됩니다.

등록한 운영 기기에서 `#inquiries`를 열고 **문의·상담 → 새 문의**를 누르거나 기존 행에서 **수정**을 누릅니다. **인계 담당자**에서 미배정, 김여울 대리님, 김의현 원장님 중 하나를 선택하고 저장하면 목록과 담당자 필터에 반영됩니다.

**인계 담당자** 아래에서 **주니어** 또는 **일반인**을 선택합니다. 분류를 확인하지 못한 문의는 **미지정**으로 둡니다. 신규·수정 화면에서는 다음 할 일을 입력하지 않습니다. 기존 기록의 해당 값은 수정 시 보존합니다.

다른 탭에서 담당자 연결을 마쳤다면 문의 창으로 돌아오면 됩니다. 새 브라우저에서 담당자 연결이 필요할 때는 **연결 파일 선택**을 눌러 현재 창에서 업무용 PC의 일회용 파일을 선택합니다. 파일은 로컬에서 읽고 같은 사이트의 등록 API로 일회용 코드만 보냅니다.

새 문의나 기존 문의를 수정할 때 **지점**에서 하남·청담·서현 버튼을 누릅니다. 지점이 확인되기 전에는 **미지정**을 선택할 수 있습니다. 기존 문의는 수정 화면에서 삭제할 수 있습니다. 삭제 확인창 바깥을 누르면 수정 화면으로 돌아가고, **삭제하기**를 누르면 목록과 문의 건수에 반영됩니다.

`문의 채널`에는 연락을 받은 곳을, `유입 경로`에는 고객이 어디에서 보고 왔는지를 기록합니다. 고객이 광고를 보고 왔다고 확인했을 때 해당 광고를 연결할 수 있습니다. 목록 제목 옆의 **총 문의**는 전체 기록 수입니다. **필터**를 펼쳐 조건을 선택하면 해당하는 기록 수가 따로 표시됩니다.

마이그레이션 `0008_inquiries.sql`로 기존 D1에 문의 테이블을 추가합니다. 이름, 연락처, 상담 메모와 다음 조치는 Worker에서 암호화합니다. 운영 기기에서만 조회하고 변경할 수 있으며, 브라우저 저장소나 방문 통계에는 상담 내용을 보관하지 않습니다.

## 비용과 검증

추가 분석 서비스·패키지·유료 API·요금제 변경 없이 기존 Workers Free/D1 한도를 공유합니다. 한도에 도달하면 저장/조회가 제한될 수 있으며 자동 유료 전환하지 않습니다. [비용 원칙](COST_POLICY.md).

`npm run build`, `npm run build:worker`, `npm test`, `npm run test:worker`로 검증합니다. 테스트에는 별도 가짜 비밀번호와 합성 방문만 사용합니다. 실서비스 검증에서 만든 합성 방문은 정확한 테스트 ID로만 삭제하며 실제 방문 기록이나 광고 이력을 삭제하지 않습니다.
