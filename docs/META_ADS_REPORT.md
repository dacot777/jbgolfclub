# Instagram 광고 자동 보고서

메인 대시보드의 **광고별 상세 실적**은 각 광고의 누적 지출, 노출, 링크 클릭, 도달을 기본으로 표시합니다. 메인 화면에서 **전체 누적 · 주간 · 월간** 버튼으로 조회 기간을 바꾸고, 주간·월간에서는 날짜 선택 목록을 열어 원하는 한 주나 한 달을 조회합니다. `#campaigns`와 이전 `#ad-report` 주소로 같은 광고 카드를 열 수 있습니다. 방문자는 로그인 없이 광고 실적을 보고, 관리자는 별도로 인증해 방문 통계를 확인합니다.

서버는 Meta 소재의 Instagram 게시물 링크와 기존 카드의 원문 링크를 대조합니다. 별도 홍보용 게시물이면 실제 광고와 카드의 대응이 확인된 경우에만 비공개 매핑을 사용합니다. 이후 수집에서 Instagram 게재 이력이 있거나 게시물·게재 위치가 확인된 새 활성·예약 광고를 발견하면 고유한 카드로 추가합니다. 썸네일을 받아 검증하면 기존 D1에 이미지 자체를 보관해 Meta의 임시 이미지 주소가 만료돼도 보여줄 수 있습니다.

## 실적 기준과 갱신 시각

- **전체 누적**은 화면 진입과 표시 중 60초 간격으로 `GET /api/meta-ads/lifetime`에서 읽습니다. 서버는 같은 광고 계정의 방문자들이 한 번의 조회 결과를 공유하도록 60초 캐시와 잠금을 사용합니다. Meta가 반환한 기간이 광고 생성일부터 현재까지 포함되는지 확인합니다. 전체 기간을 확인할 수 없으면 조회된 범위만 표시합니다. 요청 실패 시 마지막 성공 값과 그 시각을 유지합니다. 플랫폼 자체의 처리 시점에 따라 60초 뒤에도 수치는 같을 수 있습니다.
- **주간·월간**은 매시 15분에 광고 계정의 시간대·통화를 기준으로 Instagram 게재분을 조회합니다. 주간은 월요일부터, 월간은 1일부터 집계하며 진행 중인 기간에는 확인된 마지막 날짜를 표시합니다. 종료된 기간의 실적과 Meta가 이후 정정한 값의 이전 기록을 D1에 보관합니다. 일별 관측값은 기간 검산과 실제 게재 확인에 사용합니다.
- **도달**은 동일한 광고와 기간에 대해 Meta가 반환한 고유 수치입니다. 여러 광고가 한 게시물 카드에 연결되면 지출·노출·링크 클릭은 필요한 값이 모두 있는 경우에 합산합니다. 광고 간 중복을 제거할 수 없는 도달은 미확인으로 표시합니다. 신규 광고의 미수집 수치와 실제 0을 구분합니다.
- **시작과 중단**은 서로 다른 근거를 사용합니다. 광고 세트의 시작 예정일과 Instagram에서 실제 노출·지출 등 양수의 성과를 처음 확인한 날짜를 구분합니다. 과거 조회 범위에 제한이 있으면 실제 최초 게재일을 단정할 수 없습니다. 광고·광고 세트·캠페인의 중단 상태는 카드에 반영하고 이전 실적을 보존합니다. 중단 이력에는 Meta의 상태 변경 시각을 우선합니다. 해당 기록이 없으면 처음 중단 상태를 확인한 시각과 확인 가능한 마지막 게재일을 표시합니다. 화면에서는 중단이 기록된 주를 선택했을 때만 중단 표시와 시각을 보여줍니다. 정확한 변경 기록이 없으면 처음 확인한 주에 표시합니다. 광고가 재개돼도 해당 주의 이력을 유지합니다.
- **캡처 자료**는 기존 D1에 보관합니다. 메인 화면의 조회 기간과 실적 표시는 Meta 데이터만 사용합니다. 링크 클릭과 랜딩 페이지 조회도 별도 지표로 취급합니다. [캡처 기록 기준](REVIEWED_PERFORMANCE.md)

## 회사 광고 계정 연결

회사에서 사용하도록 승인한 Meta 앱을 통해 대상 광고 계정의 성과를 조회할 수 있는 서버용 액세스 토큰(`ads_read`)을 준비합니다. 회사 관리자가 Meta에서 발급한 토큰은 기존 Cloudflare Worker **jbgolf-connection → Settings → Variables and Secrets**에 **Secret** 유형의 `META_ADS_ACCESS_TOKEN`으로 입력합니다. 이 값은 채팅·Git·브라우저 저장소에 기록하지 않습니다. [Meta Marketing API 권한 안내](https://developers.facebook.com/docs/marketing-api/get-started/authorization/) · [Cloudflare Secret 관리](https://developers.cloudflare.com/workers/configuration/secrets/)

Git 제외 파일 `wrangler.production.jsonc`의 `META_AD_ACCOUNT_ID`에는 대상 광고 계정 번호, `META_ADS_API_VERSION`에는 Graph API 버전을 지정합니다. Instagram 프로필 로그인과 광고 읽기 권한은 독립적으로 설정합니다.

2026년 11월 11일 Workers Free에서 공개 광고 보고서를 배포했습니다. 기존 D1에 마이그레이션 `0005`를 적용했고 운영 Worker에 읽기 전용 토큰을 Secret으로 저장했습니다. 한국 시간 14시 29분에 시작한 첫 수집이 성공했습니다. 주간·월간 지출, 노출, 링크 클릭은 같은 기간 광고별 일일 값의 합과 일치했습니다. 광고 관리자에서 동일 조건으로 대조하는 작업은 남아 있습니다. [운영 버전 및 배포 기록](CLOUDFLARE_DEPLOYMENT.md)

## 기존 Worker에 배포하기

11월 11일 상세 카드 배포 후 두 광고의 전체 누적 조회와 첫 집행 주의 저장 결과를 운영 화면에서 확인했습니다. 시간별 수집은 일별 집행이 확인되는데 완결된 주간 기록이 없는 과거 주도 한 번에 한 주씩 보완합니다. [상세 카드 배포 검증](CLOUDFLARE_DEPLOYMENT.md#광고-상세-카드-배포-검증)

1. Cloudflare의 **Compute → Workers plans**에서 **Free** 아래에 **Current plan**이 표시되는지 확인합니다. `wrangler.production.jsonc`의 Worker 이름과 D1 ID가 기존 리소스와 일치하는지 대조합니다. `keep_vars: true`로 원격 변수를 유지하고, 운영에 `INSTAGRAM_APP_ID`가 설정되어 있으면 기존 공개 값을 로컬 운영 설정과 동기화합니다. [운영 리소스 및 배포 기록](CLOUDFLARE_DEPLOYMENT.md)
2. 기존 운영 D1에서 적용 이력을 확인하고 추가 마이그레이션만 반영합니다. `0005`에는 계정 기간별 보고서, `0006`에는 광고 목록·기간 이력·중단 이력·썸네일, `0007`에는 방문자가 공유하는 누적 조회 캐시가 있습니다.
3. 프런트엔드 및 Worker 검사를 마치고 `npm run deploy:worker`로 기존 Worker에 배포합니다. 예약 실행은 매시 15분에 광고를 갱신하고 매일 UTC 00:00에 기존 정리·토큰 유지 작업을 실행합니다.
4. 배포 후 로그인하지 않은 브라우저에서 메인과 `#campaigns`를 열고, 광고별 누적 결과의 조회 시각·기간을 확인합니다. 주간·월간 보관값, 카드 썸네일, 중단 광고의 이력이 유지되는지 점검합니다. 광고 관리자에서 완료된 주 하나를 같은 광고·기간·시간대·Instagram 게재 위치로 좁혀 지출·노출·링크 클릭·도달을 대조합니다.
