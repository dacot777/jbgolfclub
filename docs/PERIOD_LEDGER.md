# 기간별 증가분과 전체 누적 성과

사용자 지시(2026-11-06): 현재 두 광고의 수치를 **2026-10-29~2026-11-06** 첫 보고 구간으로 저장합니다. 이후 새 누적 인사이트가 전달되면 이전 누적 기준값을 차감한 증가분을 다음 기간에 저장하고 새 누적 원본은 전체 누적 성과에 반영합니다. 주간업무보고 메뉴는 제거합니다.

## 최초 기준 기록

원본 캡처의 날짜 필터는 전체 기간/7일 집행으로 표시되었지만, 사용자가 첫 보고 구간을 명시적으로 정했습니다. 따라서 원본을 삭제·수정하지 않고 각 광고에 별도의 lifetime 기준 기록과 selected_period 기준 기록을 추가했습니다. `basis=user_assigned`, `sourceSnapshotIds=[원본 ID]`로 사용자가 지정한 업무 보고 구간임을 구분합니다. 이를 새로 확인한 Meta 날짜 필터로 취급하지 않습니다. 광고 설정 일정도 변경하지 않습니다.

원본 2건과 새 기준 기록 4건이 보관됩니다. 조회 기간에는 실제 수치가 있는 **2026.10.29 — 2026.11.06**과 **전체 누적 성과**만 표시하고, 아직 받지 않은 다음 기간을 만들지 않습니다. 첫 구간은 달력상 9일이며 이후 7일 구간과 건수의 전주 증감률을 무조건 비교하지 않습니다.

## 다음 누적 인사이트가 들어올 때

1. 각 광고의 새 캡처가 ‘전체 기간 누적’인지 먼저 확인합니다. 이미 특정 주만 조회한 값이면 다시 차감하지 않고 해당 기간의 직접 기록으로 보관합니다.
2. 새 누적 원본을 새 ID의 lifetime으로 저장할 준비를 합니다. 누적 시작점은 기존 기준과 동일해야 하며, 종료일과 캡처 기준을 확인합니다. 기존 기준을 덮어쓰지 않습니다.
3. `src/lib/incremental-performance.ts`의 `deriveIncrementalSnapshot(previous,current,newId)`를 호출해 증가분을 검증합니다. 같은 광고·같은 누적 시작일·더 나중의 종료일이어야 합니다.
4. 기간 시작은 **이전 누적 종료일 다음 날**, 종료는 **새 누적 종료일**입니다. 다음 금요일인 2026-11-13 자료가 전달되면 예시 구간은 11월 7~13일이지만, 실제 자료를 받기 전에는 저장하지 않습니다.
5. 새 누적 원본과 증가분을 함께 새 기록으로 추가합니다. 증가분에는 `basis=cumulative_difference`, `sourceSnapshotIds=[이전 누적 ID,새 누적 ID]`가 들어갑니다. 원본/이전 기간은 유지합니다.
6. API와 화면에서 전체 누적이 최신 lifetime인지, 기간 선택은 증가분인지, 이전 구간이 계속 조회되는지 확인합니다. 실제 회사 수치는 공개 GitHub 소스/번들/테스트에 넣지 않습니다.

## 지표 계산

- 광고비·프로필 방문·웹사이트 방문·조회수·게시물 참여·링크 클릭·랜딩 페이지 조회·공감·3초 이상 재생은 양쪽에 값이 있을 때만 누적 차이를 계산합니다. 빠진 값은 null, 실제 0은 0으로 보존합니다.
- 새 누적값이 이전보다 작으면 집계 정정·범위 변경 가능성이 있으므로 계산을 중단하고 원문을 검토합니다. 음수를 0으로 만들지 않습니다.
- **조회한 사람**은 중복 제거된 고유 인원이므로 누적 차이를 주간 고유 인원으로 사용하지 않습니다. 해당 기간을 직접 조회한 수치가 없으면 증가분의 viewers는 null입니다.
- 프로필 방문당·웹사이트 방문당·링크 클릭당 비용은 누적 비용끼리 빼지 않습니다. 기간 지출 증가분 ÷ 같은 목표 결과 증가분으로 다시 계산하고 원 단위 반올림합니다. 결과 0 또는 값 누락이면 비용은 null입니다.
- 증가분은 ‘누적 인사이트의 순증’이며 Meta의 해당 날짜 직접 조회와 다를 수 있습니다. 소급 집계와 정정이 의심되면 임의로 확정하지 않습니다.

## 전체 누적과 코멘트

`rowsForSelection(data,'latest')`는 광고별 최신 **lifetime**만 선택합니다. 더 늦게 저장된 selected_period 증가분이 누적값을 대체하거나, 원본+증가분을 중복 합산하면 안 됩니다. 기간 선택은 해당 날짜와 일치하는 selected_period 최신본만 표시합니다.

원본/기간별 `commentary`에는 assistant가 새 자료를 분석한 짧은 코멘트를 저장할 수 있습니다. 첫 기록만 있는 지금은 숫자 요약을 유지합니다. 데이터가 쌓이면 같은 목표의 비용 효율·동일 기준의 증감·주의할 차이를 실제 수치에 근거해 작성합니다. 서로 다른 목표의 결과를 섞거나 길이가 다른 구간의 건수 증감률을 ‘전주 대비’라고 단정하지 않습니다. UI는 해당 조회 자료의 저장된 코멘트가 있으면 이를 ‘한 줄 결과’에 우선 표시합니다. 페이지에서 유료 AI API를 호출하지 않습니다.
